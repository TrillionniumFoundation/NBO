# R16 publication source and evidence contract

Each scientific family has an immutable numerical source **S** and complete evidence commit **E**. The delivery source **D** joins the four completed families with final author text, four compilable document roots, preservation maps, and review receipts. The delivery workflow rebuilds and audits those sources before creating one child **F** that adds the four PDFs and final publication records. All three review branches are created together at that same F.

Exact scientific commits and canonical paths are in `PUBLICATION_SOURCES.json`. Numerical outcomes never enter a pass condition. Positive, negative, equivalent, and unresolved comparisons remain in the complete scientific reports. Numerical source, selected candidate, inference-family, and protected-report changes cannot be introduced as editorial corrections.

## Assembly without downloading the training payload

D starts from complete menu E and has four ordered E parents: menu, replication, signed mechanism, and economic robustness. The other three canonical evidence subtrees and summary subtrees are grafted by their existing Git tree identities. Existing raw objects are reused, without another upload.

Before D is created, the assembler compares every incoming E leaf, all scientific closures, all historical leaves, and the latest review against the prospective D tree. Source overlaps must agree in mode and object identity. Only the three reviewed publication roots move to their exact archives. Author text, generated roots, retained components, maps, and new receipts enter through an explicit byte-hashed whitelist. A private index and `write-tree --missing-ok` construct the tree while large raw blobs remain absent locally. Object preparation preserves the shared index and working branch.

D is published on `revision/econometrica-nbo-r16-delivery-source-2026-10-04`. Its configuration contains no self-referential D hash: the workflow receives D externally as its immutable GitHub commit. `CURRENT_SOURCE_CLOSURE.json` and `results/current_source_closure.tsv` are generated only after final roots and all publication gates. The table is outside the TeX input graph, avoiding a hash cycle.

## Bounded checkout and complete evidence preservation

The workflow uses non-cone sparse checkout and the `blob:none` filter selected by `actions/checkout`. Publication source and small metadata are materialized first. Frozen manifests then select exact dependencies and report inputs. All new replication, signed-mechanism, and economic-robustness files are materialized. Menu materialization uses the exact analysis files in all 128 frozen transport receipts: complete confirmation observations, candidate and work records, and scalar assessments required by the unchanged reporter.

Complete trees remain available as metadata. `git ls-tree -rz` supplies every path, mode, and identity without querying missing-object sizes. Every omitted raw menu leaf is checked against E, D, the exhaustive evidence manifest, and its transport receipt. Receipts retain SHA256, length, and Git blob identity for every original file. Materialized files receive additional independent byte checks. `FULL_PAYLOAD_GIT_AUDIT.json` is a required fourth metadata file in menu's canonical and summary roots. Its 128-trial counts, original-file and byte totals, staging identity, and final-audit digest must match the full transport inventory.

Each conventional E has exactly its S as parent. Menu E has exactly its verified complete staging tip as parent. Immutable commit headers establish these facts in shallow checkouts. The unchanged menu reporter checks the source-to-staging ancestry; publication explicitly fetches its required 130-commit metadata chain with `blob:none`. Saved-data replay draws no new innovations and selects no new candidates. The selected-input ceiling is five GiB; available disk is checked before expansion.

## Independent source, report, proof and document gates

The audit first binds publication inputs to D. Scientific modules are imported only after every file in their numerical source closures is verified. Standard families recheck every trial, candidate, worker inventory, process environment, and declared count. Menu checks the original inventory through source-bound transport receipts and all materialized analysis bytes. Each frozen reporter runs in a fresh process and output directory; every report file must match its immutable canonical counterpart byte for byte.

The four new error allocations are 0.01 for replication, 0.01 for economic robustness, 0.01 for the signed account, and 0.02 for menu. Menu divides its allocation into 0.018 for 216 primary events and 0.002 for 128 scalar events. The author-added replication-attainment table is independently compared with every protected target-count record. Earlier failed source validation and its exact archived workflow remain in the attempt history, with explicit evidence that fitting and confirmation did not start.

Editorial checks reconstruct the old seventy-file closure and compare complete statements and proofs after only comment, whitespace, and input-path normalization. Every old label must remain in a current scientific document. A fresh temporary repository reruns the integrator and reconstructs all four roots, retained components, and maps. Each generated file must agree with both its current bytes and its reviewed D leaf.

The four-document build resolves cross-document references through reference auxiliary files. The original title and authorship remain. The English abstract has at most 150 words. All eighteen referee replies must be present. No development placeholders, undefined references or citations, duplicate destinations, missing glyphs, or horizontal overflow may remain. Compilation records include tool versions, page counts, and digests.

Automated layout checks render every page and inspect extracted word boundaries for blank pages and clipping. `FINAL_VISUAL_REVIEW.json` records actual inspection of every page in all four final documents before D. Its exact source fingerprint and document page counts must match CI. Automated rendering diagnostics remain distinct from the visual judgment.

## Build and final publication

The local final review build, run from the repository root, is:

```sh
python revisions/2026-10-04-r16/code/integrate.py --write-roots
python revisions/2026-10-04-r16/code/build.py --publication
```

The four outputs are R16 `build/ECTA.pdf`, `build/supp.pdf`, `build/applications.pdf`, and `build/response.pdf`. Source and status files must already describe completed evidence and final text. The workflow performs the complete publication tests, saved-data report replay, source and proof checks, rebuilt PDFs, all-page rendering, and final audit before constructing F.

The source ledger hashes finalized predecessor records. The payload manifest covers every public R16 file, including raw leaves preserved outside the bounded working tree. The last audit hashes that ledger and manifest; it does not contain its own future F identity. F is constructed through a private index as D's single child. The publisher verifies its entire tree and makes one atomic push with an empty creation lease for each target:

- `revision/econometrica-nbo-r16-2026-10-04`
- `revision/nbo-paper-r16-2026-10-04`
- `revision/econometrica-nbo-r16-referee-ready-2026-10-04`

All three targets must be absent before the transaction and resolve to the same verified F afterwards. An existing review branch cannot be force-replaced. Workflow artifacts retain the four PDFs and the source, evidence, compilation, and layout receipts.
