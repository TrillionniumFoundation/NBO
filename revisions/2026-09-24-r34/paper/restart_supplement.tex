\section{Restart-propagated lower bounds: verifier and complete cohort}\label{app:restart}
\subsection{Precise feasibility class}
For a Markov randomized rule, the conditional expected continuation values $J_t^\pi(x)$ and $C_t^\pi(x)$ include subsequent action randomization as well as the model shocks. Feasibility requires $J_t^\pi(x)\ge V_t(x)-\varepsilon$ for every $t,x$. It does not require each action in the support of the rule to satisfy this inequality on its own. For a history-dependent extension, impose the analogous conditional expected inequality after every history for which a continuation is being certified. An initial-distribution-only expected constraint defines a different problem and does not justify recursive use of future feasible-continuation lower bounds. These definitions explain exactly the class covered by Theorem~\ref{art-thm:restart}.

\subsection{Verifiable finite object}
The serialized closure stores the model and version, horizon, tolerance, installed-rule name, the canonical input-certificate SHA-256, the complete ordered support-hash list, local multipliers, every $A_t$, every $m_t^\mu$, an action selector for each minimum, and the source selector for the outer maximum. The terminal $A_T$ is identically zero. Stored rational knots include zero and one, are strictly ordered, and have separate function values. Every open interval has an affine formula. This representation distinguishes values at ties from their one-sided limits and remains valid when an installed rule induces jumps.

The fresh-process checker first verifies all support and base certificates, rather than treating their hashes as proofs of validity. A hash identifies the exact object; Bellman comparisons establish its validity. It then reconstructs the action expressions in equations~\eqref{art-eq:restart-z}--\eqref{art-eq:restart-m}. For each local minimum it checks domination by every action expression and equality at its supplied selector. For the outer maximum it checks domination of every source term and equality at the source selector. It verifies $B\le A\le C^{\widehat\pi}$, the terminal condition, horizon and multiplier identities, and both reported integrals. All selector values must be legal integers, including those at isolated knots. Every comparison examines the union of rational knots and both limits of each resulting open affine interval. The optimizing envelope routine is disabled in the constructor module, the shared arithmetic module, and the base-audit module.

These comparisons are sufficient for exact min/max identities: a supplied minimum lying below all alternatives and equaling one alternative is the true minimum, and the dual argument proves a maximum. No optimizer is needed to check these certificates. The checker still uses exact partition overlays, rational arithmetic, and file parsing; these costs are timed. It is an independently executed checker sharing an exact arithmetic library, not a formally verified proof assistant or a fully independent second arithmetic implementation.

\subsection{Adversarial and finite-tree tests}
The mutation suite requires rejection of a negative local multiplier, an omitted multiplier row, an inflated isolated lower-bound point, an inflated isolated minimum point, an illegal minimizing action, a nonintegral outer selector, an incorrect terminal value, a missing date, a changed base hash, a changed support hash, a false integrated gap, and a changed tolerance. Eight support mutations and eight base-summary mutations are also retained. A malformed object is never repaired silently by the checker.

At each of four rational initial states the finite-tree test enumerates the three first actions and all nine shock-contingent second-action pairs. It next enumerates all 378 unordered equal mixtures of the 27 plans. Mixtures sharing the first action use the conditional average second-stage value after each observed shock; different first actions reveal which branch of the mixture was chosen, and each corresponding continuation is checked separately. This realizes a behavioral randomized rule with no additional remembered private-state constraint. The test rejects no action merely for failing an individual operating test. Only plans or mixtures satisfying the actual conditional operating inequalities enter the lower-bound comparison. The stored test record reports both the total and the eligible counts, so nonvacuity is auditable.
