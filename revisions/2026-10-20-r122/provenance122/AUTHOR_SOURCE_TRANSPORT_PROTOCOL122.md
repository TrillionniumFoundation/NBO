# R122 exact author-source transport and ordinary-source promotion

This is an administrative delivery protocol after the completed scientific run. It changes no experimental sample, actor, Bellman objective, acceptance test, timing observation, or statistical family. It is not a new scientific preregistration.

The repeated large connector transfers left some unpublished administrative files unavailable. Their losses and unknown costs remain disclosed under `runtime_recovery_after_upload_reset/UNAVAILABLE_UPLOAD_ADMIN122.json`. No unavailable file is represented as recovered from its former hash. The current author files, actual preflight PDFs and real failure receipts have new, explicitly recorded identities.

## Exact small-payload delivery

1. Select an explicit repository-relative list of existing ordinary author and administrative files. The snapshot builder rejects paths outside this revision/workflow scope, symbolic links, and a changed frozen scientific member. It compares only selected Git paths against the observed branch head; it does not traverse every historical object for size metadata.
2. Preserve every changed file in a deterministic ZIP with its actual bytes, SHA256, Git blob identity, mode, and expected old Git blob. Already identical paths are recorded separately. No source is reconstructed from an unavailable older identity.
3. Split this exact ZIP into parts of at most 180 KiB. Each base64 connector payload therefore remains below 256 KiB including routine metadata. Publish manifest and parts incrementally without changing any author's ordinary target path. The final trigger is published only after every part has an actual remote identity.
4. On the exact triggered GitHub source, the separately reviewed promotion driver verifies its own source, the frozen scientific inventory, all part/archive/member hashes, and each expected old target blob. It reconstructs ordinary files, then rereads their size, SHA256, Git blob and mode. No PDF or economic computation is called.
5. A temporary Git index preserves the current remote descendant. Only declared native targets and this run's closed custody receipts may change. Both source guards and old/new target guards protect concurrent work. Publication uses a normal non-force push, followed by exact native Git readback. Its terminal status and complete parent clock are retained in a separate small artifact rather than recursively placed in their own commit.
6. The promoted ordinary native commit is not yet the final author release source. After native readback, a separate source commit binds final release configuration, all actual manuscript inputs, fixed scientific evidence identities and the final build workflow. That runner builds the actual publication PDFs and referee package. Local preflight PDFs remain separately named and hashed.

## Costs and status

The preparation receipt records only its actual serial packaging clock. Connector operations, promotion, actual publication build, and final CI have distinct receipts. Nested stages are not added to an already charged parent. Previously interrupted and unavailable work remains unknown; the whole-study exact total remains null. A successful source promotion is neither a scientific rerun nor a claim of final-package or final-author-CI success.

No existing review branch is changed. All source and native publications are confined to `revision/econometrica-nbo-r122-action-information-2026-10-20`.
