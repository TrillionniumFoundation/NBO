## Bounded execution segments

Each segment invokes the unchanged F independent driver through the unchanged I schema adapter, with an external wrapper of `exact121.evaluate_action`. The wrapper sees the same unique `(policy key, bins)` requests as the frozen driver. It returns a cached result only at the next exact position in the verified original request prefix, preserving all numeric fields and the original evaluation's saved `seconds`. It reconstructs Fraction-valued fields rather than fitting or rounding them. It must exhaust the old prefix before any new call.

An uncached request calls the unchanged original `exact121.evaluate_action` with the unchanged terminal primitives, trace, bins and 32-step rule. Its actual elapsed primitive call is measured. After the cumulative measured duration of new primitive calls reaches 300 seconds, the next uncached request raises a dedicated `PlannedCheckpoint` before doing any new work. This is checked only between complete evaluations. Returning the preceding evaluation first lets the frozen driver append its complete result and update its cache. Cached requests are still allowed after the threshold; a segment can finish naturally if no further new call is required.

A planned checkpoint is a nonterminal administrative outcome, exit75. The unchanged F exception path and I finally block may emit files labelled failed; those native artifacts and their traceback remain untouched and are explicitly attributed to the planned checkpoint. They are not mathematical failures, economic successes, or completed independent stages. Unexpected exceptions remain unexpected failures. No automatic change of data, model, mesh, thresholds or ordering is permitted.

Segment traces contain only freshly evaluated terminal witnesses. Replayed historical evaluations are identified separately. Thus a segment is never passed to statistics or reported as a canonical complete witness bundle, even if its unchanged driver reaches all claims. Each segment's original trace, manifests, input receipts, output records and F/I receipts remain untouched. This avoids copying the entire historical trace at every checkpoint.
